# 已知问题与风险

以下问题仍需团队继续验证，不应把当前网页当作生产级室内定位系统。

## P0：浏览器本身没有真实室内坐标

- 浏览器不能直接读取 UWB、BLE 或 Wi-Fi 指纹原始数据。
- 当前网页只在人工校准或外部定位接口提供坐标时显示精确位置。
- 步数只显示计数，不再自动移动地图位置。
- 需要学校或团队部署定位基础设施。

## P0：外部定位与楼层图坐标仍需标定

- 外部系统输出的 x/y 必须与 1F/2F 标准化平面图使用同一百分比坐标系。
- 需要现场标定至少 4 个控制点，校正旋转、缩放和偏移。
- 不同楼层的坐标系必须分别验证。

## P0：平面图拓扑未完成官方复核

- 当前房间热点、走廊和楼梯来自人工近似标定。
- 路线可能穿过不存在的墙或遗漏实际通道。
- 必须用学校官方 CAD/PDF/矢量图与现场走测修正。

## P1：东南出口门位置需复测

- 当前门点按用户红圈估计为 `x:91, y:88`。
- 需在现场用多张照片、平面图尺度和外部定位坐标复核。
- 门外点到百度地图的衔接也需要实测。

## P1：楼层切换依赖人工确认

- 浏览器和指南针无法可靠判断用户是否已经下到另一层。
- 当前由“我已到楼梯，下一层”等明确操作推进。
- 后续可使用气压计、二维码节点、BLE Beacon 或 UWB 楼层标签。

## P1：百度地图跳转体验不一致

- 不同手机可能打开百度地图网页或唤起 App。
- 需要 iOS Safari、Android Chrome、微信内置浏览器分别回归。
- 正式上线建议申请百度地图开放平台 Key 并接入官方坐标转换。

## P1：指南针设备差异

- iOS 需要用户手势授权。
- 部分 Android 浏览器只提供相对方向。
- 相对方向只能辅助转向，不能当绝对罗盘。
- 屏幕旋转或系统校准后可能需要重新点击“校准方向”。

## P2：部署与版本管理

- 临时 Cloudflare Quick Tunnel 会失效，不能用于正式二维码。
- 正式测试入口应使用 GitHub Pages、学校服务器或固定 HTTPS 域名。
- 每次稳定版本应打 Git tag 并保留可下载压缩包。
