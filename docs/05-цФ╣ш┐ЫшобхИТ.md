# 下一阶段改进计划

## 第一阶段：验证数据准确性

1. 获取一号楼官方 CAD/PDF/矢量平面图
2. 逐个核对所有教室编号、楼梯、卫生间、出入口
3. 现场测量走廊长度、楼梯位置和房间中心点
4. 绘制可交互的 SVG/GeoJSON 室内地图

## 第二阶段：解决室内定位

优先选择以下方案之一：

### 方案 A：蓝牙信标

- 在楼梯、走廊节点、教室门口部署 BLE Beacon
- 通过微信小程序蓝牙接口或原生 App 读取 RSSI
- 使用三角定位或指纹定位

### 方案 B：UWB

- 部署 UWB 基站和标签
- 获得厘米级坐标与楼层信息
- 通过 WebSocket/API 注入前端

### 方案 C：Wi-Fi 指纹

- 使用学校 AP 的 RSSI 指纹
- 建立离线指纹库
- 由学校网络中心或第三方定位平台提供 API

无上述基础设施时，浏览器传感器只能做“路线级辅助导航”，无法实现地图级实时精准定位。

## 第三阶段：完整导航产品化

- 增加后端服务管理 POI、教室、路网和版本
- 增加室内地图编辑器
- 用真实路网替换当前简化走廊节点
- 增加路线重规划、偏航判断、语音播报
- 增加多建筑室内图
- 增加多人测试和埋点分析
- 增加无障碍路线、拥挤度、开放时间

## 第四阶段：百度地图生产接入

- 申请百度地图开放平台 Key
- 使用官方坐标转换服务
- 配置合法域名
- 处理 App 唤起失败时的 Web 回退
- 室外导航全流程由百度地图负责到终点

## 建议团队分工

- 地图数据：官方平面图核对、SVG/GeoJSON、POI
- 定位算法：BLE/UWB/Wi-Fi 接入、传感器滤波、步态检测
- 前端交互：地图渲染、路线动画、底部面板、权限流程
- 后端：POI/楼层/版本管理、定位服务、日志
- 测试：iOS、Android、微信内置浏览器、校园实地测试
